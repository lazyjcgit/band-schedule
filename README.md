# 手环课表

把整学期课表发到**小米手环 9** 上，抬手就能看今天上什么课、下一节课在哪、几点开始。

电脑端直接用蓝牙连手环，**不需要手机 App，也不需要小米运动健康**。

> 目前只在**小米手环 9**（代号 `n66`，型号 `M2345B1`）上验证过。

## 功能

**手环上**

- **今日课表**：日期和周次，每节课的起止时间、地点、老师；课名太长自动截断
- **「下一节课」页**：大字显示开始时间和地点，下课后自动切到下一门
- 数据存在手环本地，退出重进还在

**电脑上**

- **读课表**：`.ics` 日历文件（课表软件、教务系统导出的都认），也可以直接粘贴文本
- **取绑定密钥**：登录小米账号自动获取（支持二次验证），也可以手动填
- **一键装手环端应用并下发课表**，最后手环会回一条确认

## 怎么用

电脑端界面上有四个步骤卡片，照着点就行。

### ① 选择课表

点「**选择课表文件**」选 `.ics`，或者点「**粘贴文本**」手打。解析后会显示预览。

手打格式（每行一门课）：

```
课程名 周几 节次 周次 教室 教师
高等数学 周一 1-2 1-16 A101 张三
大学英语 3 5-6 1-16 B203 李四
体育 五 3-4 1,3,5,7 操场
```

- 周几：`1~7` 或 `周一~周日`
- 节次：`3` 或 `3-4`
- 周次：可以省略（表示每周都上）；写多个用**英文逗号**，如 `1,3,5`
- 字段之间用空格或中文逗号分隔

### ② 获取绑定密钥（authkey）

手环的蓝牙通道需要一条**绑定密钥**（authkey），这是小米的硬性设计。

点「**登录并获取**」→ 填小米账号密码 → 如果账号开了二次验证，会弹出一个小窗口让你完成。
登录成功后密钥和手环地址会一起填好。

也可以自己填密钥（32 位十六进制）：在小米运动健康的日志里能找到。

### ③ 连接手环

1. 手环戴在手上、蓝牙打开、**屏幕亮着**（抬腕点亮）
2. 确认地址框里是手环的蓝牙地址，形如 `AA:BB:CC:DD:EE:FF`
3. 点「**连接**」

几个容易踩的点：

- **手环不会出现在扫描列表里。** 小米手环不回应电脑的蓝牙查询，所以扫不到它是正常的 ——
  用地址连就行，不要一直点扫描。
- **不要先在 Windows 设置里添加这个设备。** 那样配对会让手环把连接交给手机批准，
  屏幕上出现「请在手机上确认连接」就卡住了。
- **手机别占着手环。** 连接时把手机的蓝牙关掉、或退掉小米运动健康。
- 「**连接时重新配对**」保持默认勾选（连之前会先清掉系统里的旧配对记录），更稳。

### ④ 安装应用并同步课表

1. 点「**安装/更新手环端应用**」——它会自动找程序目录里的 `.rpk`，不用你选文件
2. 点「**同步课表到手环**」

状态栏最后会出现这样一句，说明真的成功了（这是**手环回的确认**，不是电脑自说自话）：

```
手环已确认收到，手环显示 42 门课
```

然后手环上打开「手环课表」就能看到了。

## 手环上怎么操作

- 主界面就是今天要上的课（顶部一行小字是诊断信息：版本、总课数、今日课数、周次）
- 点**底部按钮**进「**下一节课**」页，左上角返回
- 打开应用时会**自动向电脑请求一次同步**（电脑没连着就用手环里已存的数据）

要重新同步的话，在电脑上再点一次「同步课表到手环」即可。

## 常见问题

先看界面上的状态提示和错误框，它会把卡在哪一步直接写出来。
出问题时点右上角的「**查看运行日志**」，内容可以一键复制。

| 现象 | 原因 / 处理 |
| --- | --- |
| 扫描列表里没有手环 | 正常现象，手环不回应蓝牙查询。直接填地址连 |
| 连不上 / `No RFCOMM channel available` | 手环被手机占着：关掉手机蓝牙，或退掉小米运动健康 |
| 认证失败 | 绑定密钥（authkey）不对。点「登录并获取」重新取，或手动填对 32 位十六进制 |
| 手环说「请在手机上确认连接」 | 先在 Windows 蓝牙设置里删掉这条设备的配对记录，再连一次 |
| 提示手环端应用未安装 | 点「安装/更新手环端应用」，rpk 就在 exe 旁边 |
| 手环显示「课表接收不完整」 | 在电脑上再点一次「同步课表到手环」；或重启手环上的应用 |
| 手环显示「等待电脑连接…」不动 | 电脑端要先连上手环（连上后手环端应用才会被叫起来） |

手环端渲染有疑问时，可以用仓库里的调试插件（`tools/build-oronbox-plugin.py` 打包）
在 OronBox 里直接给手环发一份课表，验证是渲染问题还是下发问题。

## 项目结构

```
├── pc/                       电脑端（Flutter / Dart）
│   ├── lib/src/schedule/     课表解析（ICS / 纯文本）
│   ├── lib/src/band/         连手环、取 authkey、下发课表
│   ├── lib/src/device/       设备层与小米协议实现
│   └── windows/runner/       原生部分：蓝牙 SPP 通道、文件选择框、二次验证窗口
├── band/band-schedule/       手环端快应用（JavaScript + .ux → .rpk）
└── tools/                    构建脚本与测试
```

## 构建

仓库里**只有源码**，不含签名密钥、第三方 SDK 和构建产物。要自己构建：

**电脑端**

```powershell
cd pc
flutter doctor        # 需要 Visual Studio 的 "develop Windows apps"

# 「登录并获取」的二次验证窗口需要 WebView2 SDK，约 20 MB，自己下一次：
powershell -File windows\scripts\install_webview2_sdk.ps1 -Version 1.0.4191.47

flutter pub get
flutter build windows --release
flutter test          # 48 项测试
```

或者直接 `python tools/build_pc.py`，产物会连同手环端 rpk 一起放进 `dist/pc/`。

**手环端**

```powershell
powershell -ExecutionPolicy Bypass -File tools/build-all.ps1
```

这一步会先跑完测试和各项检查，再打包出 `.rpk`。

**关于签名密钥**：`band/band-schedule/sign/` 不在仓库里 —— 私钥公开等于把"以你的名义发版本"
的能力交出去。**自己构建时用自己的密钥即可**：手环是按**包名**授权的，不校验签名者，
换密钥不影响安装和使用。
